# Complete the Agents and Workflows experience before connecting service keys

Focus on the two panels from the approved live-readiness plan. People should be able to create, configure, save, inspect, test where possible, and manage agents and workflows without encountering unfinished screens or controls that claim an action happened when it did not. Both panels must be business-agnostic: workflows express a company's own call triggers, conditions, data, and actions rather than a restaurant, sales, or support script. Preserve aviroh's current VoiceLine-inspired, neutral-and-forest-green look, shared cards, modular tabs, plain product copy, and mobile layout. Do not wait for LiveKit, AI provider, phone-provider, or email credentials to complete key-independent work.

## Agents

1. **Agent list:** Make search, status, sort, templates, duplicate, archive, restore, and delete fully consistent. Add a selection-based bulk archive flow and show real published/deployed environments and last editor when that information is available. Use honest empty states and safe confirmations.
2. **Studio:** Keep the existing General, Conversation, Voice and AI, Knowledge, Tools, Call behavior, Policies, Test, and Versions areas, but remove or replace the empty Advanced tab. Add description, character counts and insertable supported variables where the saved prompt can actually use them. Let each business write its own instructions and connect its own knowledge and tools; examples are optional starting points, not required industry-specific fields. Keep the saved-draft/unsaved state accurate across every field and attachment.
3. **Readiness:** Show attached knowledge processing and failure states and each tool's real test status. Present model/key availability using the existing provider status without exposing keys; distinguish a saved configuration from one that can run. The publish checklist must show actionable, verified blockers and never announce readiness when required tests or credentials are absent. Do not block saving drafts merely because a live service is not configured.
4. **Testing and versions:** Keep text testing available only with a usable provider and voice testing gated by real service status; display clear, direct next steps otherwise. Compare selected versions with readable field-level old/new values, especially prompts and call settings. Restore a version to an unsaved draft, then save explicitly; show release notes and real deployment destinations.

## Workflows

5. **Visual builder:** Use an n8n-like **node-and-connection canvas**, tailored to aviroh rather than an n8n dependency or generic automation clone. Offer a trigger node, condition branches, and reusable action nodes for the supported call actions (tool, webhook, tag, and existing supported outputs). Users can add, connect, reposition, configure, duplicate, and delete nodes; a side panel edits the selected node. Provide a readable ordered/list alternative on small screens and for keyboard users. No industry-specific mandatory fields or hard-coded business process.
6. **Data and execution:** Let businesses map supported conversation fields and literal values to tool inputs and webhook payloads. Validate graph connections (one start, no cycles or orphan nodes, valid branch outcomes), references, input types, values, and conditions before activation. Evolve the saved workflow shape and executor together so branches, mapping, and node order actually run as drawn for manual runs and incoming call events. Migrate existing linear workflows without changing their behavior. Only expose executable node types; email, end call, live wait, and handoff must not claim completion until their execution paths exist.
7. **Manage and run:** Make create/edit/duplicate/enable/delete flows robust across workspace changes. Show the workflow's trigger, agent scope, action path, and readiness before activation. Manual runs should clearly distinguish a selected past conversation from a run with no call, and warn when a node needs call data. Highlight the path taken and show skipped/failed/succeeded node results, duration, and failure cause in run history; do not imply a requested handoff actually ran.
8. **Live readiness:** Replace the static service notice with status based on existing connection signals. When live execution is unavailable, keep editing and safe manual tests available but explain that call-triggered actions will wait for service setup. Surface failed workflow runs from real records, with a way to open their details.

## Verification

9. Browser-test the signed-in Agents and Workflows flows on desktop and phone widths in light and dark modes: create from scratch/template, edit/save/reload, publish validation, compare/restore, bulk archive, create/connect/branch/configure workflow nodes, reject invalid graphs, duplicate, enable, manual run with and without a call when data exists, and inspect the executed path in history. Verify an existing linear workflow still runs after migration and unauthorized users see read-only or permission feedback. Clean up test records. Check the latest build and runtime diagnostics.

## Technical boundaries and dependencies

- Reuse the existing authenticated workspace queries, design components, provider registry, and server functions. Scope every read and mutation to the selected workspace and preserve role checks. Extend key-independent data contracts only where essential to support a real frontend control (for example graph execution, field mapping, editor attribution, or readiness); do not build a pretend frontend backed by no execution path. Add this business-agnostic requirement to the project roadmap during implementation.
- Do not create fake agent replies, fake calls, placeholder analytics, or simulated workflow success. Credential-dependent text/voice calls, telephony, live handoff/wait behavior, automated call-triggered runs, and email delivery remain blocked until their services are configured. They should have accurate disabled/needs-setup states rather than dead buttons.
- Scope here is Agents and Workflows and their directly related readiness/history surfaces; other console sections and pricing are not redesigned in this pass.
